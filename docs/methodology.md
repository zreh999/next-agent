# 本命回响 · 推荐方法

## 产品回答什么问题

本命回响（Agent Resonance）帮助玩家探索可能喜欢的特工玩法，并提供可以实际尝试的任务。本版用16道原创情境题形成五维玩法偏好，与按2026-11-11官方目录核对的30名特工画像比较，输出至多三名候选。这是有日期的角色覆盖快照；后续新增角色需要重新审阅和更新目录。

它不测量稳定人格、真实操作水平或竞技潜力。回答反映当前自述偏好，会受到经历、队友、当天状态和对题目的理解影响。特工画像与映射规则也是产品的人工设计，不是已获验证的心理学对应关系。

## 问卷与心理学概念的边界

五个维度是开局主动性、信息偏好、预案偏好、变化偏好和协同偏好。情境设计可以参考行为选择、信息搜集和动机等心理学概念；具体依据与题目设计见[问卷设计说明](question-design.md)。

这些原创题目不属于正式心理量表，没有常模、稳定性或测量效度证据，也不把用户划成互斥的固定人格。每个维度至少通过六道能实际区分答案的情境共同观察，避免一道题直接决定角色。题目覆盖数量是设计与工程约束，不是效度证明。

## 从答案到候选

1. 校验完整题库版本与答案，拒绝缺失、重复或不属于当前问卷的输入。
2. 每道相关题的选项贡献为0—4。对同一维度的有效题目求平均后除以4，得到0—1的偏好位置；未覆盖维度不作为零分参与计算。
3. 将用户画像与维护者整理的特工画像做加权L1比较。基础距离为 `distance(u, a) = Σ wᵢ × |uᵢ − aᵢ| / Σ wᵢ`，分母只包含有效参与的维度权重。
4. 在基础距离之外，按公开规则考虑用户愿意承担的练习和沟通负担；明确排除的角色不参加候选。经验作为背景信息，不被自动当成能力或人格。
5. 使用确定性的排序与平分规则选择候选，再从实际参与计算的维度和相关回答生成理由。

首推是当前规则下最贴合的合格候选；相近替代优先寻找分差在容差内且职责不同的角色；换种打法在负担意愿内探索不同职责。候选不足时减少数量，不为了固定展示三名而忽略约束。

内部贴合分只用于当前规则内的比较，不是“有多少概率适合该特工”、准确率或技能评分。不同规则版本的数值不能直接当作能力升降来比较。

## 可解释性与可视化

推荐应说明哪些偏好与特工画像接近，以及哪项职责、节奏或练习投入可能带来负担。理由由实际参与排序的因素产生，不得脱离计算独立生成讨喜评价，也不应将偏好写成优势保证。

本机报告保留相关情境的答题依据。下载的分享卡仅包含偏好图和候选，不包含逐题答案或试玩反馈。报告网址只标识本机记录，不是公开分享链接。

五维图表展示当前问卷形成的偏好位置，候选对比图帮助理解差别。它们不代表常模百分位、技能等级或与其他玩家的排名；分数较高不代表更优秀。候选是尝试选项，不是对具体地图、阵容和版本环境的唯一正确答案。

## 内容版本

当前问卷为 `3.0.0`、角色库为 `2.0.0`；计分规则另行维护版本。每份结果保留生成它的题库、规则和角色资料版本，以及角色、维度和推荐快照。相同版本与相同输入应能复现相同推荐；新内容不悄悄改写旧报告。

修改结果含义或排序时，需要说明受影响的版本，提供修改前后样例，并检查理由是否仍与计算一致。游戏更新可能改变角色玩法，因此资料日期和覆盖目录需要独立审阅。

## 试玩反馈

试玩任务引导用户观察职责乐趣、操作与管理负担、继续练习的意愿。反馈是体验记录，不以胜率或击杀表现代替个人喜好。

当前反馈仅用于个人回顾，不上传给维护者，不自动训练模型或修改全站权重，也不将首次回答定义为永久人格。用户可以主动提供不含个人信息的样例参与人工讨论。

## 本机报告与图片分享

答案、报告快照和试玩反馈保存在生成它们的浏览器本地存储中，不依赖 Cookie 会话或服务器数据库。复制报告地址不会把记录传给对方；他人的浏览器没有这份报告。

当前版本不要求游戏账号、战绩或官方 API，也不提供账号恢复、云端分享创建与撤销或跨设备同步。清除站点数据或更换浏览器后无法自动恢复记录。分享使用下载图片，具体存储及部署说明见[部署文档](deployment.md)。
