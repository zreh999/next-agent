# v0.2.0 验证记录

日期：2026-11-11。环境：Windows、Node.js 24.22.1、Next.js 16.4.6、Prisma 7.10.1。

## 本轮已实际完成

- `npm run typecheck`：通过，包含新增图鉴、品牌配置、题库与测试文件。
- `npm run test:compat`：5个测试文件、44项全部通过。这与默认配置运行同一组断言；仅使用原生配置加载、保留路径及线程池，避免受限Windows环境的路径检测子进程。
- 内容审计：问卷2.0.0为16题、64选项；角色库2.0.0为30名，完整官方名单逐一比对；五个维度各有6—7道有效区分题。
- 30名中英文名对照国服官方公开名录，职业与机制对照全球官方页面。来源见 `agent-sources.md`。
- `npm run test:smoke`：真实HTTP接口7组、144项断言全部通过，包括版本/完整中文名录、测评创建、私有查询隔离、反馈持久化、分享脱敏、跨源拒绝、撤销及无效答案处理。Cookie值没有输出。
- Next.js源代码编译阶段成功，独立类型检查通过；完整生产构建未完成，原因见下节。
- 使用Next官方支持的自定义开发服务器启动当前源码预览，3000端口首页实际返回200，页面包含新品牌和新标题；health实际返回0.2.0。此预览入口保存在本任务work目录，使用NEXT_AGENT_WORKER_THREADS=true，让开发模式的动态路径检查在线程中运行；项目本身仍使用标准Next启动命令。此设置未增加权限，也没有禁用检查。

## 本轮受限与未执行项目

- 默认Vitest启动在本机Vite路径检测阶段遇到`spawn EPERM`，兼容模式已完成同一组44项断言；没有修改依赖源码或放宽系统保护。
- `next build`完成源代码编译后，Next调用TypeScript 7 CLI时受到子进程限制（`spawn EPERM`）。框架线程模式不能替代TypeScript 7 CLI的独立进程，因此仍未完成生产构建。保留的可选线程开关只用于受限开发环境的动态路径处理，没有通过跳过类型检查来宣称构建通过。
- Chromium启动同样被子进程限制阻止，因此本轮完整浏览器回归及新截图尚未执行。新增图鉴/旧草稿隔离的两项端到端测试已写入，但不计为已通过。
- 额外权限的自动审批服务返回连接/加密推理上下文故障，明确表示动作未执行、不是不安全判定。因此未执行GitHub登录、创建或推送；此前的用户同意仍有效，不需要提供密码或令牌。
- PostgreSQL真实实例、Docker、远端GitHub Actions和公网部署仍未实测。已有schema、迁移和部署说明不等同于这些环境通过验证。

## 复现检查

```sh
npm ci
npm run db:generate
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

受限Windows环境可以改用 `npm run test:compat` 执行相同单元测试。API检查在本地服务启动后运行 `npm run test:smoke`，使用 `API_BASE_URL` 可指定测试服务。该检查不需要浏览器或提升权限；实际执行结果以本轮记录为准。

历史通过记录另见 `verification-v0.1.md`。旧版43项单测、7项浏览器测试和生产构建曾通过，不能据此认为新版已经通过相同检查。

心理测量效度、竞技收益和真实玩家契合效果不属于工程测试结论；本版仍为心理学启发的原创玩法探索工具。
