## 复现命令

```sh
npm ci
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Windows 子进程受限时，可执行 `npm run test:compat` 运行相同单元断言。浏览器测试运行前必须先完成静态构建；测试以静态文件服务器提供 `out/`，不启动 Next.js 后端。

本机标准 `npm run build` 在源代码编译成功后，Next.js 调用 TypeScript CLI 子进程时受到 `spawn EPERM` 限制。未关闭类型检查，也未修改依赖源码。此次先独立完成完整类型检查，再使用 Next.js 官方支持的 `compile` / `generate` 构建阶段和可选线程模式导出全部页面；第二次生成让框架刷新初次编译的导出清单。随后检查实际 `out/` 文件和 HTTP 响应。GitHub Actions 保留标准 `npm run build` 和浏览器测试，以验证正常 Linux 构建路径。

## 必须覆盖的静态版行为

- 项目子路径 `/next-agent/` 的首页、图鉴、问答、方法、报告、试玩页面可打开，并支持直接访问和刷新。
- 完整问答生成报告，推荐规则与内容版本沿用已有定义。
- 刷新与重新打开页面后，本浏览器的报告和反馈仍可读取；修改偏好会创建新报告。
- 另一个浏览器上下文仅拿到报告 URL 时不能读取原本机记录。
- 下载的结果卡为有效 PNG，手机小屏没有横向溢出。
- 核心流程不发起 `/api/` 请求，也不依赖 Cookie 会话或数据库。
- 存储被禁用、写入失败或记录损坏时给出可理解的提示。
